# 时光套餐与订单恢复

价格版本 `photo-retail-cny.v1`，人民币整数分。单人、双人合照同价。

| 玩法 | 交付范围 | 整单总价 |
| --- | --- | --- |
| 走过一生 `lifespan-21` | 0–100 岁，每 5 年一张，共 21 张 | ¥9.90 |
| 指定年龄 `selected-age` | 0–100 岁任意整数年龄，共 1 张 | ¥5.90 |
| 一生衣橱 `wardrobe-series` | 一个主题系列内，全部适用款式 | ¥9.90 |

衣橱按目标年龄、人数筛选可用款式，订单确认前展示张数。款式多寡不改变整套价格。不可用系列不能下单；旧基础款不作为新套餐出售。双人照每人须分别授权，不能由发起者代为同意。

## 服务端流程

`GET /v1/photo-products` 读取版本化价格；`POST /v1/photo-purchases` 根据已验证照片和授权创建不可变订单。服务端决定金额、年龄清单或款式清单，客户端不能提交金额、支付状态或任意款式列表。订单范围与照片来源通过 `scopeSha256` 绑定。

订单资源 `/v1/photo-purchases/{purchaseId}` 提供逐年龄或逐款结果。`checkout` 准备商户订单；`confirm` 查询受信商户状态；`fulfill` 仅在服务端确认付款后提交生成。微信原生支付返回成功不代表服务端已确认付款。生成、逐款恢复和旧时间轴重试都会核对所属订单，退款订单不能再次生成。历史无套餐绑定的作品保留既有恢复路径。

每个款式独立提交、追踪和恢复。同一订单重试使用固定指令标识，进程中断后能继续未提交项。下载复用原图的摘要、照片授权和质量门禁；不把等待回执或部分完成显示为整套完成。

## 商户服务接入条件

API 使用 `LTM_WECHAT_PLATFORM_BROKER_URL` 与 `LTM_WECHAT_PLATFORM_BROKER_TOKEN_FILE` 配置受信平台服务。现有本地 client-integration-broker 不提供微信商户支付能力，不能用其替代真实付款验收。

平台服务必须实现认证的 `POST /v1/wechat/photo-checkouts`：请求含主体验证上下文、`purchaseId`、服务端产品报价（`sku`、`priceVersion`、`amountMinor`、`currency`、`imageCount`、`scopeSha256`），幂等键固定到订单。返回 `ltm.photo-checkout.v1`，`checkoutId` 必须等于 `purchaseId`，并包含唯一商户 `orderId`、相同金额、币种与范围摘要。后续复用平台服务已有的原生支付意图及验签后的支付状态接口；API 拒绝不匹配报价或范围的响应。缺少平台服务时保留订单并明确失败，不开始生成。

## 用户恢复与验证边界

“我的订单”仅在用户主动继续时核对并发起付款；打开页面不会自动付款。订单每页 25 笔，通过“更多订单”继续查找，其余订单不会被静默丢弃。已支付订单先确认状态，再继续处理；待确认、取消付款或退出后台都保留订单。衣橱支持逐款原图保存、剩余图片继续保存、权限拒绝后的手动设置和逐款重试。

本地测试运行真实 HTTP、SQLite/PostgreSQL、授权、签名回执、生成指令持久化和文件校验。商户、人物及回执内容使用明确的测试边界，没有付费推理。开发者工具的合成页面验收不代表真实收费、真机相册权限、真实模型、身份一致性或逼真度已通过；这些项目仍为 NOT_RUN / NOT_CERTIFIED。
