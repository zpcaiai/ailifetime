# 照片评分服务接入与本地验收

本轮在 `1e9efd8` 基础上接通实际图片字节到 B15 的服务入口。它接入外部感知评分服务，**没有内置或下载人脸、年龄、逼真度模型权重**。本地测试的评分服务返回明确标注的合成测量值；真实 HTTP、JPEG/PNG 文件、SQLite、授权、签名回调及发布检查实际执行。这不能证明模型准确或照片逼真。

## 运行链路

`POST /v1/timelines/{commandId}/quality` 只接受 `service_account` 且具备 `media.quality.evaluate` 的账号，purpose 必须为 `age_transformation`。请求必须有 `Idempotency-Key`，正文只有：

```json
{"targetAge":37,"asset":{"id":"candidate-id","sha256":"<实际64位SHA256>","mimeType":"image/png","width":1024,"height":1024,"byteLength":123456}}
```

这里的字节长度、尺寸和摘要必须来自实际结果文件，示例不能直接用作数据。消费者不能调用此接口，也不能传入分数、阈值、模型或图片 URL。启用评分器后，旧 B15 HTTP 接口禁止直接提交带图片绑定的评分；既有未绑定的历史工具保持兼容。底层受信任服务代码仍有 B15 能力权限，不能把工作负载凭据交给客户端。

服务依次执行：

1. 读取租户内的原始 B14 或逐年龄重试命令、B07 intake 和有序人物映射；检查当前授权、取消及待对账状态。
2. 从 B07 的 canonical SHA256、长度、JPEG 类型和尺寸解析原始参考图，不采用调用者传入的参考照。读取原图和候选结果的实际字节并校验摘要。
3. 选择唯一匹配的校准配置：人物模式、年龄区间、与原图的年龄跨度、生成路由、模板及渠道。缺失或重叠均拒绝评分。当前生成路由为 `generation-engine`；真实供应商和模型的进一步分层仍待生成适配器提供可信出处。
4. 发送原始参考图和输出图的 base64 字节、有序人物、目标年龄、摘要及模型/校准版本到固定评分服务。换装还发送已签名交付的年龄照片作为第三张参考图及实际目录里的服装指令；始终保留最初上传照作为身份锚点。
5. 检查返回值的请求摘要、模型版本/摘要、校准 ID、人物位置、全部维度和有限数值。逐人计算年龄分并取最弱人物的身份、年龄、五官保持分，不做平均掩盖。
6. 再次检查命令、原素材和当前授权，通过原 B15 校验与 SQL 持久化。报告保留模型、每维分数/阈值、逐人年龄估计及置信度、请求/响应摘要、完整校准快照与快照摘要；不存原图、base64 或人脸向量。
7. 原有 B17 安全证明及签名生成回调仍是发布条件。仅有评分通过不会发布图片，也不会创建出图命令。低分由供应商回调标记 `QUALITY_REJECTED` 后进入现有最多三次的逐年龄补图流程；低年龄置信度返回 `review`，不能自动放行。

年龄分使用配置的误差容忍值：置信度达到门槛时为 `max(0, 1 - abs(估计年龄 - 目标年龄) / ageToleranceYears)`；置信度不足时年龄分为 0 并转复核。这是明确可复现的门控公式，**容忍值与阈值的填写不构成校准有效性证明**。身份及逼真度测量由配置的评分模型产生，不能用哈希相等、清晰度或随机值代替。

## 服务协议与启动配置

上游固定入口为 `POST /v1/photo-scores`，协议版本为 `ltm.photo-score.request.v1` / `ltm.photo-score.response.v1`，闭合字段见 `services/api/src/photo-score-contract.ts`。响应需返回有序逐人身份相似度、年龄估计/置信度、五官保持分，以及姿态、背景、伪影、手牙眼、清晰度、逼真度；换装另需逐人服装匹配及区域保持分。任何缺项、未知项、错人、错模型、非有限值或错误请求绑定都报错。

显式配置以下变量，未配置时不启用评分，接口返回服务未配置：

| 变量 | 内容 |
| --- | --- |
| `LTM_PHOTO_SCORER_URL` | HTTPS origin，不允许用户信息、路径、query 或 fragment |
| `LTM_PHOTO_SCORER_TOKEN_FILE` | 绝对路径，私有普通文件，非符号链接，包含工作负载令牌 |
| `LTM_PHOTO_SCORER_POLICY_FILE` | 绝对路径，非符号链接且不可被组/其他用户写入的 JSON 校准数组 |
| `LTM_PHOTO_SCORER_CHANNEL` | 与配置内渠道完全一致，例如 `wechat` |
| `LTM_PHOTO_SCORER_TIMEOUT_MS` | 可选，500～30000 毫秒，默认 10000 |
| `LTM_PHOTO_SCORER_ALLOW_HTTP_LOOPBACK` | 仅 `local` / `test` 可显式为 `true`，允许本机 HTTP 联调 |

校准数组元素使用 `PhotoPolicy` 闭合结构，模型权重摘要及版本必须固定，不提供默认模型、阈值或自动备用分数。配置包含 ID、模型版本/摘要、context、目标年龄与跨度的最小/最大值、年龄容忍值、最低置信度，以及九项正阈值（换装十一项）。换装模板 ID 为 `wardrobe:` 加上有序 styleId 数组 JSON 的 SHA256，按实际服装组合选择配置。

本地还需 `LTM_TIMELINE_MEDIA_DIRECTORY` 指向含真实原图及输出图的受控内容寻址目录，`APP_ENV=local` 或 `test`。main 在启用评分而没有媒体读取器时拒绝启动。文件读取器仅支持本地/测试；生产需接入经确认的租户隔离存储及部署服务，不能复用测试目录承载用户媒体。

每个人必须已有原图 `age_transformation` 授权，以及 `quality_assurance` 下 `media.asset:{sourceAssetId}` 的 `process` 授权和该质量报告的处理授权；换装另需原有 `wardrobe` 授权。报告 ID 由 `photoQualityId` 确定，包含租户、命令、年龄、输出/参考摘要及校准配置。服务不会替参与者授权。

校准快照、其摘要和报告 ID 内的配置指纹使用项目 `canonicalJson`，在数据库规范化字段顺序后仍可复算；等价配置调整字段顺序不会重复评分。缓存同时校验摘要及快照内容。旧的非规范摘要记录不会被静默改写或重新认定通过。请求和响应摘要继续遵循原有协议字节规则。

请求使用稳定 `photo-score:{requestSha256}` 推理幂等键。已持久化的同一报告可直接复用，不再推理；模型服务应按该键去重。网络失败不产生通过报告，允许调用者重放同一请求；本接口不自动重试推理。实际供应商的成本、幂等能力与并发限制仍需接入验收。模型版本/摘要是服务申报与配置的匹配检查，不是独立的远程权重证明。

## 失败、安全与证据

超时、断连、非 JSON、未知版本、错绑或超大响应均关闭发布。HTTP 响应在读取时受 512 KiB 上限约束，超限即取消，不会先完整缓冲。拒绝重定向；图片来自服务端读取器而非外部 URL。模型响应或请求被篡改、文件损坏、授权在推理过程中撤回，均不能写入通过记录。日志仅记录状态与错误类型，不记录原图、模型响应全文或令牌。

读取文件后的发送前、缓存返回前及评分落库前都会重新检查当前计划、任务状态、原图及报告的质量处理授权。读取期间撤权或取消任务会阻止推理；缓存结果同样需要当前授权。已发送的外部请求无法靠后续撤权追回，供应商删除及传播能力仍需真实服务验收。

评分涉及原图、生成图、目标年龄与项目内人物标识。它们仅发往运营方显式配置且已获授权的评分服务，不允许用于跨用户识别或任何保险、医疗、信用、就业等决定。生产接入还需确认评分服务的地域、保留期限、删除传播、访问控制和子处理者清单；本轮没有向真实服务发送个人照片。

本地执行证据及 SHA256 在 `evidence/B15/photo-scorer-local-evidence.json`，R01～R05 映射见 `photo-scorer-traceability.json`。测试覆盖单人/情侣 21 张、换装参考、逐人低分、低置信度、错绑、撤权、损坏、故障恢复、幂等及流式超限；测试评分值只属于外部模型边界夹具。
