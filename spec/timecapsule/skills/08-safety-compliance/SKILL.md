# 内容安全与合规门

## 启用条件
当任务触及本领域时读取本 SKILL，先核对 `AGENTS.md`、`IMPLEMENTATION_PLAN.md`、`contracts/`。不要仅凭该文件生成未验证的生产代码。

## 输入
隐私分类、平台要求、AI标签

## 输出
前后审核、复审/申诉、可审计导出。每个变更必须产出机器可读契约、实现、测试、可复现命令与 E0-E5 证据清单。

## 操作顺序
1. 读取关联 schema/API、模板与现有实现；列明前后置条件、授权边界、状态与异常。
2. 先写正反向行为测试，再实现最小闭环；优先重用共享的领域组件，避免针对单模板复制逻辑。
3. 检查并发与恢复、容错、可观察性、个人信息处理、成本与灰度风险。
4. 运行本地静态测试，生成 E0/E1 报告；如具备环境，执行 E2/E3/E4 否则将缺口标 BLOCKED。
5. 输出文件 diff、契约版本、迁移策略、回滚策略和评审检查项。

## 不可违反
高危内容直接阻断；不允许 AI 背景合成结果覆盖已经人工确认的身份信息、年龄日期或价格；不得编造外部服务联调结果。

## DoD
- [ ] 正常/边界/异常路径用例覆盖
- [ ] 禁止越权和重复收费/发放
- [ ] 成本与隐私记录可审计
- [ ] 稳定输出与回滚路径就绪
- [ ] 证据链链接可追踪
