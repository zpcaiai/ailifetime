# AGENTS — Codex / Antigravity 执行协议

## 任务执行前
1. 读取 README、contracts、catalog 和对应 Skill；输出 `implementation-intent.md`（受影响组件、接口契约、非目标、风险、依赖）。
2. 建立测试基线；若缺少历史仓库上下文，不能宣称适配既有代码已完成。
3. 禁止跳过身份/授权、内容治理、资金流、删除链、导出 AI 标识等关口。
4. 所有功能按垂直切片实现：数据模型→API→作业→渲染→小程序页面→测试→观测。

## 设计不可变量
- 不得使用用户客户端传入的价格、user_id 或对象存储路径作为授权依据。
- 订单支付成功仅依据经签名校验、幂等处理且必要时主动查询的商户端结果。
- 不得从 HTTP 请求同步阻塞等待生图模型；作业需重试、超时、隔离和可取消。
- 消费/退款/余额变更必须事务性记账并可对账；一笔成功支付不得重复发放权益。
- 同一 render request + revision + idempotency key 对用户只产生一个逻辑作品。
- 用户未授权不调用人像生成；人像素材不可默认公开或用于训练。
- 所有付费导出必须添加所适用的 AI 显式/隐式标识，不得提供移除标识接口。
- 具有精确文本字段的模板，文字和二维码用确定性引擎叠加，文字不得由扩散模型猜测。
- 管理员可以停用模板，历史作品保留 manifest、模板版本和生成来源以供审计。
- 用户照片、儿童照片等的存储/处理应实施对象级鉴权和最小保留策略。

## PR 输出格式
PR 描述必须包括: 业务验收条件、契约改动、风险清单、测试矩阵、故障注入、成本估计、截图/像素验证、rollback、Evidence manifest。

## 独立验证
E0 静态/Schema；E1 单元+性质；E2 契约与模拟依赖；E3 真实数据库/对象存储/队列沙箱；E4 独立 QA 真模型沙箱/微信支付沙箱或可用测试模式/小程序设备；E5 线上逐步发布+SLO观测。无可核实证据不得升级等级。
