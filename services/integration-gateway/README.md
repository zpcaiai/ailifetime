# Integration gateway

The integration gateway accepts provider callbacks only after native signature validation. It preserves the exact request bytes, uses a tenant-and-route-bound Redis lease/outbox state machine, stores artifacts in KMS-encrypted S3 with Object Lock, signs a provider-bound business event and its scoped evidence with an Ed25519 key from AWS Secrets Manager, and submits one atomic `external-event.apply` command through the API `/v1/commands` endpoint. It never registers evidence separately from the state projection. A retry after an API failure reuses the same persisted event, evidence ID, nonce, timestamps, signature, request body, and idempotency key; an expired envelope is atomically cleared and re-verified, while a corrupted cache entry is cleared and rejected.

Production startup is fail-closed. Configure `APP_ENV=production`, a fixed `LTM_TENANT_ID`, a `rediss://` `LTM_REDIS_URL`, the `LTM_EVIDENCE_S3_*` settings, and managed references for the evidence signing key and commerce-binding request/response keys. `LTM_API_COMMAND_URL` must end exactly in `/v1/commands`; `LTM_API_BEARER_TOKEN_FILE` must be an absolute projected workload-identity token file and is reread for every command. The workload principal needs only `external-event:apply`, and `LTM_API_EVIDENCE_PURPOSE` should be `external_business_event_projection`. Inline bearer tokens, evidence private keys, Apple roots, Google service-account JSON, and WeChat key material are rejected.

Google Play uses Application Default Credentials/workload identity by default. Set `LTM_GOOGLE_AUTH_MODE=managed-service-account` and `LTM_GOOGLE_SERVICE_ACCOUNT_REFERENCE=secret-manager:...` only when a managed long-lived key is explicitly required. Apple production requires online certificate checks and an Apple app ID. WeChat and store callbacks require the signed internal commerce-binding resolver; tenant, account, order totals, and currency are never accepted from callback URLs, query strings, or client headers. Partner webhook policies are loaded from `LTM_PARTNER_WEBHOOK_POLICIES_REFERENCE` and bind route, batch, operation, provider, subject path, state policy, signature scheme, retention, and evidence environment.

The managed partner-policy document uses version `ltm.partner-webhook-policies.v1`. Every route must declare `routeId`, the supported `batchId`/`operation`/`kind`/`provider` tuple, `signatureScheme`, `verificationKeyReference`, retention/body/skew limits, required JSON paths, subject/event/time/correlation paths, an allowlisted `eventTypeMap`, and allowlisted `canonicalClaimFields`; `sequenceField` and state validation are optional but paired fields are enforced. Only B74, B89, and B98-B102 atomic event contracts are accepted. A callback cannot choose its tenant, reducer, patch, ledger entry, or command transition.

Health endpoints are `/health/live` and `/health/ready`. Readiness requires both Redis callback/evidence stores and a readable, safely permissioned workload token file. Callback delivery leases are owner-token protected and completed entries are retained for seven days, covering the configured provider retry window. S3, provider, commerce-binding, and API failures still fail individual callbacks with a retryable 503; no third-party receipt is synthesized.
